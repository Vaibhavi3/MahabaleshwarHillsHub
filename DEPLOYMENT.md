# Deploying Mahabaleshwar Hills Hub

Free-tier path to a real public URL: **Neon** (Postgres) + **Render** (backend API) + **Vercel** (frontend). All three have generous free tiers and connect directly to this GitHub repo.

## 0. Push the current code

Commit and push everything in this repo (including `backend/static/products/` - the seeded product photos, ~56MB - and `scripts/products_seed.json`) to GitHub before starting.

## 1. Database - Neon

1. Create a free account at neon.tech, create a new project.
2. Copy the connection string it gives you (starts `postgresql://...`). Add `?sslmode=require` to the end if it isn't already there.
3. Keep this handy for step 2.

## 2. Backend - Render

1. Create a free account at render.com and connect your GitHub account.
2. New -> Blueprint -> select this repo. Render will detect `render.yaml` at the repo root and propose one web service (`mahabaleshwar-hills-hub-api`).
3. Before the first deploy, fill in the env vars marked `sync: false`:
   - `DATABASE_URL` - the Neon connection string from step 1.
   - `CORS_ORIGINS` - put `http://localhost:3000` for now; you'll add the real Vercel URL after step 3.
   - `STRIPE_SECRET_KEY`, `STRIPE_PUBLISHABLE_KEY` - from your Stripe dashboard (test mode keys first).
   - `STRIPE_WEBHOOK_SECRET` - leave blank for now, set after step 4.
   - `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET` - from your Razorpay dashboard (test mode keys first).
   - `ADMIN_EMAIL`, `ADMIN_PASSWORD` - the login you'll use for `/admin` on the live site.
   - `SECRET_KEY` is auto-generated by Render - leave it.
4. Deploy. Once live, note the service URL, e.g. `https://mahabaleshwar-hills-hub-api.onrender.com`.
5. Seed the production database once, using Render's **Shell** tab on the service:
   ```bash
   python -m app.seed
   ```
   This loads all 294 seeded products/variants from `scripts/products_seed.json` and creates your admin user.

Note: Render's free tier spins the service down after 15 minutes of inactivity - the first request after idle takes ~30-60s to wake up. Fine for a launch; upgrade later if that matters for your traffic.

## 3. Frontend - Vercel

1. Create a free account at vercel.com, import this repo.
2. Set **Root Directory** to `frontend`. Vercel auto-detects Create React App.
3. Add env vars:
   - `REACT_APP_API_URL` = `https://mahabaleshwar-hills-hub-api.onrender.com/api` (your Render URL from step 2, with `/api`)
   - `REACT_APP_STRIPE_PUBLIC_KEY` = your Stripe publishable key
   - `REACT_APP_RAZORPAY_KEY_ID` = your Razorpay key ID
4. Deploy. You'll get a URL like `https://mahabaleshwar-hills-hub.vercel.app` - **this is the link to post on Instagram.**

## 4. Wire it back together

1. Back on Render, update `CORS_ORIGINS` to your real Vercel URL (e.g. `https://mahabaleshwar-hills-hub.vercel.app`), redeploy.
2. In your Stripe dashboard, add a webhook endpoint pointing at `https://mahabaleshwar-hills-hub-api.onrender.com/api/payments/stripe/webhook`, subscribed to `payment_intent.succeeded`. Copy the signing secret into Render's `STRIPE_WEBHOOK_SECRET` env var, redeploy.

## 5. Test before going live

With everything still in **test mode** (Stripe test keys, Razorpay test keys):

1. Visit your Vercel URL, browse products, add to cart, register an account, check out.
2. Complete one real test-mode payment through both Razorpay and Stripe to confirm orders land correctly and admin dashboard (`/admin`, logged in as your admin user) shows them.
3. Only once that works, switch `STRIPE_SECRET_KEY`/`STRIPE_PUBLISHABLE_KEY`/`RAZORPAY_KEY_ID`/`RAZORPAY_KEY_SECRET` on Render (and the two `REACT_APP_*` keys on Vercel) to your live keys, and redeploy both.

## Known gaps to fix before/soon after launch

- The 9 "Handmade Bags" products have no photos in the current data (see `scripts/CATALOG_REVIEW.txt`) and were not seeded. Add real photos and re-run `scripts/prepare_catalog.py`, or add them manually via `/admin`.
- `scripts/CATALOG_REVIEW.txt` also lists the Home Slidders folder-to-SKU mapping (best-effort, sequential) and a handful of colour/photo mismatches - worth a quick visual spot-check against the live site.
- Render's free Postgres/web-service tiers have cold starts and low resource limits - fine to launch, but if Instagram traffic spikes, consider upgrading the Render plan.
